# 远端行情数据源与代理配置改造

## 背景

当前应用原先依赖本地行情文件导入，用户需要手动准备数据文件，使用成本高，也无法快速检查不同数据源的可用性。

本期目标是改为直接请求开源免费行情接口，第一期覆盖沪深京股票、ETF、指数，并支持多数据源切换。默认使用东方财富，用户可在应用内切换到新浪财经、网易财经 163、腾讯/QQ 财经。

在接入远端接口后，实际调试发现部分接口在当前网络环境下可能失败：

- 东方财富历史 K 线接口在当前直连环境下可能返回 `ERR_EMPTY_RESPONSE`。
- 网易财经 163 历史接口在当前直连环境下可能返回 `502`，且当前仅按股票日线能力接入。
- 新浪财经、腾讯/QQ 财经在当前验证中可返回数据。

因此需要同时提供数据源状态测试入口和显式网络代理配置入口，便于用户判断是数据源能力问题、接口不可用，还是本机网络访问问题。

## 方案概述

第一期采用主进程统一拉取行情数据、渲染进程只发起查询和展示结果的方式。

- 数据源默认值：东方财富。
- 数据源范围：东方财富、新浪财经、网易财经 163、腾讯/QQ 财经。
- 市场范围：沪深京股票、ETF、指数。
- 兜底策略：不再使用本地文件兜底。
- 切换方式：通过“数据源”弹窗测试和切换，不在顶部工具栏直接放数据源下拉框。
- 网络策略：默认所有行情请求直连，不读取 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY` 等环境变量。
- 代理策略：新增“代理”弹窗，用户可手动启用 SOCKS5 或 HTTP 代理后重新测试/刷新数据。
- 启动策略：启动加载默认使用东方财富；如果首次自动加载失败，可尝试其他远端源，但不回退本地文件。
- 可用性策略：东方财富保留为默认源，但需要在“数据源”弹窗中明确展示真实网络失败原因；如当前网络长期不可用，建议用户切换到新浪财经或腾讯/QQ 财经。

## 东方财富失败调查结论

本次对东方财富源的失败现象做了单独排查，结论是当前失败更接近网络出口或请求栈与东财 `push2/push2his` API 的兼容性问题，不是当前接入参数写错。

### 复现现象

- 应用内请求东方财富历史 K 线接口失败，错误为 `net::ERR_EMPTY_RESPONSE`。
- 使用 Electron `session.fetch` 直连访问同一接口，也稳定复现 `net::ERR_EMPTY_RESPONSE`。
- 东方财富官网页面 `quote.eastmoney.com` 可正常返回 200，说明不是整个东财域名不可访问。
- 东方财富 `push2.eastmoney.com` 实时接口和 `push2his.eastmoney.com` 历史接口均可能返回空响应，说明问题不只发生在 K 线接口。
- Node 直连在不同环境下表现不一致：沙箱内可能 DNS `ENOTFOUND`，真实本机可解析但 GET 后仍可能被服务端关闭连接。
- 本机 `127.0.0.1:7890` 代理链路在当前测试中也可能返回空响应或 `other side closed`，不能作为稳定修复手段。

### 已排除项

- 已验证接口路径仍为公开常见用法：`/api/qt/stock/kline/get`。
- 已验证核心参数 `fields1`、`fields2`、`ut`、`klt`、`fqt`、`secid`、`beg`、`end` 形态符合公开实现。
- 已尝试 HTTPS、HTTP、`lmt` 参数形式、浏览器常见请求头、独立 Referer、先访问 quote 页面预热 session，均不能稳定解决。
- 已验证失败不是 JSON 解析问题，因为服务端没有返回 HTTP 响应体。

### 当前处理建议

- 第一阶段不把东方财富失败硬编码兜底成本地文件。
- 东方财富仍保留为默认源和可测试源，错误详情通过“数据源”弹窗展示。
- 用户当前网络下如果东方财富失败，建议切换到新浪财经或腾讯/QQ 财经继续使用。
- 后续如需继续增强东方财富，可增加可用出口检测、域名/IP 候选池、请求栈替换或第三方数据代理，但这些都属于第二阶段稳定性增强。

## 实现改动

### 主进程数据接入

- 新增远端行情数据源模块，统一管理数据源元信息、能力校验、请求、解析和标准化输出。
- 接入东方财富、新浪财经、网易财经 163、腾讯/QQ 财经四个免费公开接口。
- 查询前按数据源能力校验周期、复权、市场类型，不支持时直接返回明确错误。
- 各数据源使用独立 Referer 和统一 User-Agent，减少跨源请求参数混用。
- 网易财经 163 使用 GBK 解码处理 CSV 返回。
- 默认请求链路改为直连，不读取系统环境代理变量。
- 显式启用代理时，按用户配置使用 SOCKS5 或 HTTP 代理。

### IPC 与持久化配置

- 新增远端行情查询 IPC：渲染进程通过统一 adapter 请求主进程数据。
- 新增数据源列表查询 IPC：用于渲染端展示可用数据源及能力。
- 新增设置项 `networkProxy`，持久化代理开关、协议、地址和端口。
- 新增代理配置保存 IPC，保存后后续行情请求按新代理配置执行。

### 渲染层交互

- 顶部工具栏保留股票代码、周期、复权、日期范围、刷新按钮。
- 顶部工具栏新增“数据源”按钮，打开数据源状态弹窗。
- 数据源弹窗展示每个源的请求状态、请求参数、记录数、耗时和错误详情。
- 数据源切换放入数据源弹窗表格中的“使用”按钮。
- 顶部工具栏新增“代理”按钮，打开网络代理弹窗。
- 代理弹窗支持启用/关闭代理、选择 SOCKS5/HTTP、配置 host 和 port。
- 状态栏显示当前数据源、证券代码、记录数、行情状态和加载状态。

### 移除本地文件兜底

- 移除本地文件导入 view model、adapter、IPC 和菜单入口。
- 应用启动和刷新只走远端数据源。
- 加载失败时展示远端请求错误，不再尝试读取本地文件。

## 测试计划(UT)

### 远端数据源模块

- 校验数据源元信息完整性：四个数据源均可被列出，默认能力符合第一期范围。
- 校验请求解析逻辑：使用 mock fetch 验证远端返回可转换为统一 `StockDataset`。
- 校验默认网络策略：存在 `HTTP_PROXY` 环境变量时，默认请求仍不走环境代理。
- 校验能力限制：网易财经 163 查询指数/ETF 时，应在请求前返回“不支持”错误，不发起网络请求。

### StockWorkspaceViewModel

- 校验默认查询参数：默认数据源为东方财富，默认证券为 `sh000001`。
- 校验刷新成功后，图表数据、状态栏和记录数更新。
- 校验数据源切换：在数据源弹窗内点击“使用”后，查询源更新。
- 校验数据源测试：可并发测试所有源，并记录成功/失败、耗时、记录数和错误详情。
- 校验代理配置保存：修改代理开关、协议、地址、端口后，应调用 adapter 保存并更新状态。

### 回归用例

- 指标计算、K 线图 adapter、旧解析器相关 UT 保持通过，确保远端数据标准化后不破坏既有图表渲染链路。

## 影响范围(建议手动测试范围)

### 基础加载

- 启动应用，确认默认使用东方财富加载 `sh000001`。
- 修改证券代码为沪市股票、深市股票、北交所股票、ETF、指数，分别点击刷新。
- 修改日期范围，确认数据量、图表和状态栏同步变化。

### 数据源弹窗

- 点击“数据源”，确认四个源都展示在弹窗中。
- 点击“测试状态”，确认每个源展示请求状态、耗时、记录数或错误详情。
- 在弹窗中点击“使用”，确认当前数据源切换成功，关闭弹窗后刷新使用新源。
- 使用网易财经 163 查询指数或 ETF，确认提示“不支持”而不是泛化网络失败。

### 代理弹窗

- 默认不启用代理时，确认请求不会依赖系统环境代理。
- 打开“代理”，配置 SOCKS5 代理并保存，重新测试数据源。
- 配置 HTTP 代理并保存，重新测试数据源。
- 关闭代理后保存，确认后续请求恢复直连。

### 图表与状态

- 切换周期：日线、周线、月线、分钟线，确认不支持的源给出明确提示。
- 切换复权：不复权、前复权、后复权，确认不支持的源给出明确提示。
- 打开/关闭 BOLL、VOL MA、B/S，确认远端数据加载后指标展示正常。
- 网络失败时，确认顶部错误提示和底部状态栏都能反映失败状态。

## 风险与后续

- 当前接入的是公开免费接口，接口稳定性、反爬规则、返回字段都不受应用控制。
- 东方财富 `push2/push2his` API 在当前网络环境下会出现服务端空响应；这不是当前代码参数错误，但会影响默认源可用性。
- 网易财经 163 在部分网络环境下可能不可用，需要用户通过代理弹窗确认是否为本机网络问题。
- 网易财经 163 第一期仅保留股票日线能力，后续如需 ETF/指数或复权，需要寻找新的网易接口或换源策略。
- 后续可新增数据源健康缓存、失败源自动降级策略、数据源优先级配置、接口返回字段监控。

## 验收标准

- 默认启动和刷新不再读取本地行情文件。
- 顶部存在“数据源”和“代理”两个入口。
- 数据源弹窗可以测试四个源，并可以完成数据源切换。
- 代理弹窗可以保存 SOCKS5/HTTP 代理配置，并影响后续远端行情请求。
- 默认不启用代理时，不读取环境代理变量。
- UT、类型检查、构建均通过。
