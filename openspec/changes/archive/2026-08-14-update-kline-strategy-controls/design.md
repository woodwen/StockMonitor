## Context

当前 K 线图表已经有两类买入/卖出标记来源：K 线指标中的 `B/S` overlay，以及策略回测选中结果传入 `KLineChartsAdapter` 的 strategy overlay。两者在视觉上都表现为 B/S 标记，且当前策略信号不受 K 线指标设置控制，容易在图表上叠加造成误读。

策略回测面板当前单独维护 `strategyStartDateInput` / `strategyEndDateInput`，并把 `dateRange` 写入 `KlineStrategySettings`。这与外部 K 线工具栏的日期范围形成两套时间来源，用户需要重复维护日期，也可能得到与当前图表范围不一致的回测结果。

本 change 仅规划用户可见行为和后续实施路径，不改代码、不提交、不 archive。

## Goals / Non-Goals

**Goals:**

- 在 K 线指标设置中新增 `策略` 信号开关，用来控制选中策略结果的图表信号标记。
- 保证 K 线 `策略` 信号开关与 `B/S` 信号开关互斥，任何时刻最多只有一套买入/卖出图表标记可见。
- 删除策略回测面板里的开始日期和结束日期输入，统一使用当前 K 线 query 的 `startDate` / `endDate`。
- 让旧版保存的策略 `dateRange` 字段不再影响 UI、回测 query 或新持久化结果。
- 更新 README、应用内使用说明书和 changelog，使用户说明与实际行为一致。
- 将需求中的“回撤设置”按“策略回测设置”处理，删除的是策略回测日期范围输入。
- 在历史 K 线缓存弹窗表格中新增 `数据源` 列，让用户能在每行缓存状态中直接看到对应行情源。
- 在历史 K 线缓存弹窗顶部区分 `单只股票缓存` 与 `多只股票缓存`，每次打开默认使用 `单只股票缓存`，不记忆上次模式。
- 将历史 K 线缓存默认勾选项调整为仅勾选 `日线` 和 `前复权`，其他周期与复权口径默认不勾选。

**Non-Goals:**

- 不新增策略模板，不改变已有均线交叉、突破回撤、RSI 超买超卖和 MACD 趋势确认的信号算法。
- 不改变回测成交模型、费用率、滑点率、评分公式或缓存完整性校验规则。
- 不为策略信号新增独立颜色、形状或样式编辑能力；本次只新增展示开关。
- 不改变分时指标的 B/S 行为，互斥范围限定在 K 线指标设置。
- 不调整最大回撤指标的计算算法、展示口径或排序逻辑。
- 不为历史 K 线缓存表格新增数据源筛选、排序或分组能力；本次只增加展示列。
- 不改变 K 线缓存底层存储 key 或缓存完整性判断模型；本次只调整弹窗默认模式、默认勾选项和请求构造入口。

## Decisions

1. K 线指标设置新增 `strategySignal` overlay 指标项，用户可见标签为 `策略`，默认关闭。

   选择这个方案是因为现有指标弹窗已经以 `indicatorDefinitions` 驱动开关、草稿、应用、取消和持久化。把策略信号纳入 K 线指标设置，可以复用现有设置入口，并让用户把 B/S 与策略标记理解为同一类图表信号。默认关闭已确认，用于保留当前 K 线 `B/S` 默认开启的既有体验。备选方案是在策略面板里新增展示开关，但那会把信号显示控制拆到另一个入口，无法满足“k线指标中新增开关”的要求。

2. `strategySignal` 与 `bsSignal` 的互斥由 model normalize 和 ViewModel 草稿操作共同保证。

   用户在指标弹窗里开启 `策略` 时，草稿中的 `bsSignal.enabled` 同步关闭；开启 `B/S` 时，草稿中的 `strategySignal.enabled` 同步关闭。normalize 需要处理旧配置和异常配置：旧配置缺少 `strategySignal` 时补齐为默认关闭；如果持久化数据异常地同时开启两者，默认保留 `bsSignal`、关闭 `strategySignal`，以延续现有默认 K 线体验。这样最新用户操作由草稿逻辑体现，旧数据迁移由 normalize 兜底。

3. 策略图表标记由 `strategySignal` 开关和选中成功策略结果共同决定。

   `KLineChartViewModel` 仍保留 `strategySignals` 作为传给 adapter 的渲染输入，但 `StockWorkspaceViewModel.syncSelectedStrategySignals()` 需要在 `strategySignal.enabled === true` 且存在选中成功结果时才传入 signals；否则传入空数组。`KLineChartsAdapter` 可以继续复用现有 strategy overlay group，收到空数组时移除策略标记，不在 adapter 里重新计算策略逻辑。

4. 策略回测 query 统一从当前 K 线 query 派生。

   `createStrategyBacktestQuery()` 应直接使用当前 K 线 query 的 `sourceId`、`symbol`、`period`、`adjust`、`startDate` 和 `endDate`，再经过现有数据源 normalize。策略面板保留策略模板、参数、初始资金、费用率、滑点率和运行按钮，但移除开始日期/结束日期输入；面板可以只读展示当前 K 线区间，提示用户通过外部 K 线日期范围调整。

5. `KlineStrategySettings.dateRange` 进入兼容读取、停止写入阶段。

   为避免旧工作区设置导致启动失败，输入类型可暂时接受旧 `dateRange`。normalize 后的运行态设置不再包含 `dateRange`，保存工作区时自然清理旧字段。回测结果仍通过 `KlineStrategyBacktestResult.query.startDate/endDate` 记录实际使用的当前 K 线区间，确保结果可复现。

6. 文档更新随实现一起完成。

   README 和应用内 `使用说明书` 需要说明：K 线指标里有 `B/S` 与 `策略` 两个互斥信号开关；策略回测日期范围来自顶部 K 线日期范围；策略面板不再单独设置开始日期和结束日期。由于这是用户可见行为变化，实现阶段还应在 `CHANGELOG.md` 的 `Unreleased / <current package.json version>` 区块记录。

7. 需求中的“回撤设置”按“策略回测设置”处理。

   已确认本 change 删除的是策略回测设置中的开始日期和结束日期，不改变最大回撤指标本身。最大回撤继续作为回测结果指标展示，算法和排序输入保持不变。

8. 历史 K 线缓存列表新增 `数据源` 列。

   `KlineCacheStatusRow.query.sourceId` 已经包含每行缓存状态的数据源身份，UI 应通过现有数据源元数据把它映射为用户可读名称，例如 `东方财富`。默认列位置放在 `名称` 后、`周期` 前，因为名称定位证券，数据源定位缓存维度，周期和复权随后构成完整 query 维度。默认列宽为 96px，适配 `东方财富` 这类短名称并减少对 `名称` 与 `缓存范围` 的挤压；如果映射不到显示名，默认展示原始 `sourceId`，避免空白。备选方案是在名称单元格里追加数据源副文本，但会降低扫描效率，也不符合“增加一列”的要求。

9. 历史 K 线缓存弹窗新增缓存对象模式，默认 `单只股票缓存`。

   模式控件放在历史 K 线缓存弹窗顶部，使用两个选项：`单只股票缓存` / `多只股票缓存`。弹窗每次打开都默认 `单只股票缓存`，不记忆上次模式选择，避免用户再次打开时误触发批量刷新。单只模式只针对当前 K 线 query 的 `symbol` 和当前显示名称构造缓存状态、刷新和清理请求；即使该证券不在自选股列表中，也允许缓存。用户显式切换到 `多只股票缓存` 后，再沿用当前自选股列表作为批量缓存对象。该模式只影响请求 items 的来源，不改变数据源、日期范围、周期和复权口径的选择语义，也不修改自选股列表本身。

10. 历史 K 线缓存默认勾选项改为 `日线` + `前复权`。

   弹窗打开时周期默认只勾选 `日线`，复权默认只勾选 `前复权`；`周线`、`月线`、`不复权`、`后复权` 默认不勾选。这个默认值与常见 K 线查看和策略回测输入更一致，也能把初次缓存任务从 9 组组合收敛为 1 组组合，减少网络请求、缓存耗时和上游限流风险。用户仍可手动勾选其他周期或复权口径，用于准备更完整的历史缓存。

11. 历史 K 线缓存模式切换保持查询条件，只重建缓存对象。

   用户在 `单只股票缓存` 与 `多只股票缓存` 之间切换时，保留当前数据源、日期范围、周期选择和复权选择，清空表格选中项并重新查询缓存状态。`刷新全部` 的语义跟随当前模式：单只模式只刷新当前证券，多只模式刷新当前自选股列表。多只模式下如果自选股列表为空，弹窗展示空状态并禁用刷新操作，避免提交空批量任务。

## Risks / Trade-offs

- [Risk] 用户运行策略回测后看不到图表策略标记，因为 `策略` 开关默认关闭。→ Mitigation：策略面板和说明书使用中性文案说明“如需在图表展示选中策略信号，请在 K 线指标中开启策略开关”；默认关闭用于保留旧版 B/S 默认展示。
- [Risk] 异常持久化数据同时开启 `B/S` 和 `策略` 时，用户期望不明确。→ Mitigation：normalize 选择保留 `B/S`，并让后续用户显式切换决定新的展示模式。
- [Risk] 删除策略面板日期输入后，部分用户找不到回测区间入口。→ Mitigation：在策略面板回测设置区域只读展示当前 K 线区间，并在 README/使用说明书中说明通过顶部 K 线日期范围调整。
- [Risk] 旧测试仍断言 `strategyStartDateInput` / `strategyEndDateInput` 或旧错误文案。→ Mitigation：实施时同步更新 ViewModel 和策略面板测试，验证回测 query 日期来自当前 K 线 query。
- [Risk] 过去默认一次缓存多只股票和多组周期/复权，用户可能以为打开弹窗会继续准备全部组合。→ Mitigation：弹窗以明确的模式控件展示 `单只股票缓存` / `多只股票缓存`，并在 README/使用说明书说明默认只缓存当前证券的日线前复权，批量缓存需要手动切换。

## Migration Plan

- 在 model 层为 K 线指标配置补齐 `strategySignal` 默认值和互斥 normalize。
- 在 ViewModel 的 K 线指标草稿开关、应用和快捷切换路径中执行互斥规则，并在开关变化后同步策略 overlay。
- 从策略面板和 ViewModel 中移除独立日期输入与 setter，回测 query 改用当前 K 线 query。
- 调整 `KlineStrategySettings` 的 normalize/clone/type 处理，使旧 `dateRange` 可读取但不再保存或驱动行为。
- 调整 K 线缓存弹窗 ViewModel 状态，新增缓存对象模式，控件放在弹窗顶部；每次打开默认使用当前 K 线 query 构造单只证券 items，不记忆上次模式；用户切换多只模式后使用当前自选股列表。
- 调整 K 线缓存弹窗默认 query，周期默认 `['day']`，复权默认 `['qfq']`，保留用户手动勾选其他周期和复权的能力。
- 调整缓存模式切换逻辑，切换时保留数据源、日期范围、周期和复权选择，清空表格选中项并重新查询缓存状态；多只模式自选股为空时禁用刷新。
- 更新 README、应用内使用说明书和 changelog。
- 运行 `yarn test tests/stock-workspace-view-model.test.ts`、策略回测相关测试、KLineCharts adapter 测试、文档相关测试，以及 `yarn typecheck` / `yarn test`。
