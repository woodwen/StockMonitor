## Context

当前分时数据结构以 `StockTimeshareDataset` 和 `StockTimesharePoint` 为核心，点位字段包含 `price`、`avgPrice`、`volume`、`turnover`，足够支撑价格线、均价线、成交量、MA/EMA/BOLL、B/S、MACD、RSI 等基于价格或成交量序列的指标。K 线侧已有 `StockCandle` OHLC 数据和 KDJ 指标定义，但分时点位缺少分钟 OHLC，因此无法直接复用 K 线 KDJ 的输入。

高级分时指标的数据前置差异较大：

- KDJ 需要分钟级 `open/high/low/close`，至少需要 `high/low/close`。
- 量比需要当前分时累计成交量和历史成交量基准。
- 换手率需要当前分时累计成交量和流通股本。
- 委比需要盘口买卖档位数量。
- 内外盘需要逐笔方向，或数据源直接提供的内盘/外盘聚合字段。
- 资金流需要带方向的成交额，或数据源直接提供的资金流聚合字段。

这些上下文不适合作为基础分时数据的硬依赖，否则会让已有分时图在部分数据源上失效。方案应保持基础分时查询稳定，同时为高级指标增加可选、可解释、可测试的数据能力。

## Goals / Non-Goals

**Goals:**

- 在分时指标体系中规划 KDJ、量比、换手率、委比、内外盘、资金流。
- 为每个高级指标定义前置数据、可用性判断、缺失数据降级和默认计算边界。
- 扩展行情源能力元数据，让 UI 和 ViewModel 能在请求前或请求后判断高级指标是否可用。
- 保持远端请求在 main process，preload bridge 只暴露 typed API，renderer 不直接请求行情接口。
- 让 model 层负责高级指标定义、参数 normalize、可用性判断和计算，chart adapter 只渲染已准备好的值。

**Non-Goals:**

- 第一版不提供投资建议、买卖建议、收益承诺或主观信号解释。
- 第一版不承诺所有数据源都支持所有高级指标；不支持的指标必须明确不可用。
- 第一版不做跨源静默拼接，例如用东方财富分时叠加腾讯盘口后伪装成同一源完整数据。
- 第一版不拆分超大单/大单/中单/小单、主力/散户等资金流分层。
- 第一版不引入新的远端请求依赖库；继续复用现有代理感知请求能力。
- 第一版不把 ETF、指数作为高级上下文的主要验收市场；这些市场缺少流通股本、盘口或方向成交数据时按不可用降级。

## Decisions

### Decision: 高级上下文作为 `StockTimeshareDataset` 的可选能力扩展

在基础分时数据之外增加规范化的高级上下文，例如分钟 OHLC、历史成交量基准、流通股本、盘口快照、方向成交聚合和资金流聚合。基础字段仍保持向后兼容；高级字段缺失时基础分时图 SHALL 继续可用。

备选方案是为每个指标增加独立 IPC 请求。该方案会让 ViewModel 编排和错误处理变复杂，也更容易在 renderer 侧形成远端数据拼接逻辑，因此不作为默认方案。

### Decision: 第一版优先支持东方财富，腾讯作为后续补充验证源

第一版实现 SHALL 优先评估并支持东方财富的高级分时上下文。原因是当前东方财富分时已有同源 delay fallback，且项目已有东方财富分钟 K 线和日线请求路径可用于分钟 OHLC 与历史成交量基准。腾讯保留为后续补充验证源，第一版不要求与东方财富达到同等高级上下文覆盖。

备选方案是同时支持东方财富和腾讯。该方案会放大接口差异、测试夹具和失败模式，容易延缓第一版可验证闭环。

### Decision: 用能力元数据表达“源支持什么”，用可用性结果表达“本次数据能算什么”

`SourceCapabilities` 应扩展分时高级能力描述，表达数据源理论支持的上下文；实际返回的 dataset 还应携带本次可用性和缺失原因。这样能处理“源支持盘口但当前证券无盘口”“源支持历史量但响应缺字段”等运行时情况。

备选方案是只在 indicator engine 内部根据字段存在与否静默跳过。该方案不利于设置弹窗、状态栏和测试定位缺失原因。

### Decision: 指标计算保留在 model，chart adapter 不计算业务指标

新增 `TimeshareIndicatorName`、默认设置、参数校验和计算函数时，应沿用 `timeshare-indicator-definitions` 与 `timeshare-indicator-engine` 的模式。chart adapter 只消费 enriched dataset 中的指标值、可用性和展示元数据。

备选方案是在 canvas 绘制时直接读取原始字段并计算。该方案会破坏现有架构边界，也难以单元测试公式与降级行为。

### Decision: 第一版采用明确的默认公式和保守缺失策略

- KDJ 默认参数为 `[9, 3, 3]`，基于分钟 `high/low/close` 计算 RSV、K、D、J；区间最高价等于最低价时 RSV 按 50 处理。
- 量比默认用当前累计成交量的分钟均值除以最近 5 个有效交易日的日均每分钟成交量；如果数据源提供更精确的同分钟累计历史基准，则优先使用并在指标口径中标记。
- 换手率默认用当前累计成交量除以流通股本。
- 委比默认用盘口买卖前 5 档数量合计计算：`(买量 - 卖量) / (买量 + 卖量) * 100%`；分母为 0 时不可用。
- 内外盘默认使用数据源逐笔方向或源端内外盘聚合字段；不从价格涨跌方向反推。
- 资金流默认提供总流入、总流出和净流入；不做主力资金分层。

备选方案是缺少字段时通过价格变化、均价或成交额推断方向。该方案容易误导用户，默认不采用。

### Decision: 展示形态分为序列指标和最新态指标

KDJ、量比、换手率可作为随时间变化的序列指标进入分时 enriched points。委比第一版只展示最新盘口快照。内外盘和资金流按数据源能力展示为序列或累计态；若只有源端累计字段，则展示累计态并标明来源。因此数据模型应允许指标值标记为 `series`、`latest` 或 `accumulative`。UI 可在分时指标设置中统一管理，但渲染时按数据形态选择副图线、量能区、tooltip 或状态摘要。

备选方案是强制所有高级指标都画成同一种线图。该方案会错误表达盘口快照这类非历史序列数据。

### Decision: 高级上下文按证券、来源和交易日缓存

历史成交量基准和流通股本 SHALL 按 `sourceId + symbol + tradeDate` 缓存；同一交易日内自动刷新应复用不变上下文。盘口、逐笔方向、内外盘和资金流 SHALL 随分时刷新更新，并在结果中保留采集时间。缓存失效时仍应允许基础分时数据返回。

备选方案是每次自动刷新都重新请求所有高级上下文。该方案会增加网络成本，并提高数据源限流和局部失败概率。

## Risks / Trade-offs

- 数据源字段不稳定 → 在 adapter 中保留源字段解析测试和清晰错误信息；高级上下文失败不应拖垮基础分时数据。
- 指标公式存在行业口径差异 → 在 design/spec 中固定第一版默认口径，并在 UI 展示中避免暗示该口径等同于交易建议。
- 历史成交量请求会增加网络成本 → 优先复用东方财富同源已有 K 线/日线接口，按 `sourceId + symbol + tradeDate` 缓存基准数据，自动刷新时避免重复请求不变上下文。
- 分时设置项增多导致 UI 拥挤 → 继续使用分组设置和副图数量限制；默认只开启现有基础指标，高级指标默认关闭。
- 盘口和逐笔方向可能只支持股票、不支持指数或 ETF → 第一版优先 A 股股票，能力元数据按市场范围表达，运行时按证券类型返回不可用原因。

## Migration Plan

- 扩展类型和 normalize 时，为新增分时指标提供默认关闭设置；已有用户设置缺少新键时按默认值补齐。
- 先在数据源 meta 中声明高级能力，默认保守为不支持；第一版优先补东方财富真实解析，腾讯作为后续补充验证源。
- 实现时保持 `fetchStockTimeshareDataset` 的基础返回兼容；新增字段全部可选。
- 更新 tests 后运行 `yarn typecheck`、`yarn test`、`yarn test tests/remote-stock-sources.test.ts`、`yarn test tests/stock-workspace-view-model.test.ts`、`yarn test tests/ipc-handlers.test.ts`，若触及打包/preload 配置再运行 `yarn build`。
- 用户可见变更实施时更新 `CHANGELOG.md` 的 `Unreleased / <current package.json version>` 区块。

## Confirmed Defaults

- 第一版优先评估并支持东方财富；腾讯作为后续补充验证源。
- KDJ 必须有分钟 `high/low/close`；缺失时不可用，不使用单点价格伪造 OHLC。
- 量比默认使用最近 5 个有效交易日的日均每分钟成交量；若源提供同分钟累计历史基准，则优先使用并展示口径。
- 换手率使用当前累计成交量除以流通股本；缺少流通股本时不可用，不用总股本替代。
- 委比展示最新盘口快照，按买卖前 5 档数量合计计算。
- 内外盘只接受逐笔方向或源端聚合字段；不根据价格涨跌推断。
- 资金流只做总流入、总流出、净流入；不做主力/散户或大单/小单分层。
- 高级指标默认关闭；不可用时禁用并展示原因。
- 第一版优先 A 股股票；ETF 和指数按能力缺失降级。
- 历史成交量、流通股本按 `sourceId + symbol + tradeDate` 缓存；盘口、逐笔方向、资金流随分时刷新更新。
