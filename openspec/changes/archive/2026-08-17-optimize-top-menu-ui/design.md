## Context

当前 `TopToolbar.tsx` 使用一个长 `Space` 顺序渲染所有按钮，并通过 `.top-toolbar { overflow-x: auto; white-space: nowrap; }` 兜底。这个实现简单，但所有入口视觉权重相近，常用行情查询和低频配置混在一起；功能继续增加时，用户更容易错过当前模式相关控件，也更依赖横向滚动。

本 change 只规划 UI 结构优化。实施时应遵守现有架构边界：React View 负责展示和触发命令，业务状态与编排仍由 `StockWorkspaceViewModel`、`AppUpdateViewModel` 和 `TradeProfitCalculatorViewModel` 提供；renderer 不直接请求远端行情接口，也不新增 IPC。

## Goals / Non-Goals

**Goals:**

- 让顶部工具栏形成明确层级：查询优先、模式参数其次、工具和设置收敛。
- 保留行情查询相关控件的直接可见性，减少用户刷新行情时的扫描成本。
- 将数据源、代理、缓存导入导出和更新检查等低频操作聚合到菜单式入口。
- 保证所有现有顶部操作仍可从顶部区域访问，且触发的 ViewModel action 不变。
- 让 K 线专属入口仅在 K 线模式下出现或可用，避免分时模式暴露不相关操作。
- 避免默认桌面宽度下出现横向滚动条，窄窗口仍保持核心查询能力可用。

**Non-Goals:**

- 不调整远端行情请求、数据源能力、自动刷新、缓存导入导出、策略回测、做T测算或更新检查的业务逻辑。
- 不新增、删除或重命名 IPC channel 和 `window.stockApi` typed bridge。
- 不修改 Electron 原生应用菜单。
- 不新增投资建议、买卖建议、荐股服务、收益承诺或类似用户文案。
- 不重做整体视觉主题，不引入新的 UI 框架。

## Decisions

1. 顶部工具栏按操作频率和任务上下文分组。

   已确认保留这些直接可见入口：证券代码输入、自选股入口、分时/K 线切换、K 线模式参数、刷新按钮和当前证券标题。它们构成行情查看的主路径，用户每次切换证券或刷新时都需要快速定位。

2. 低频配置操作进入 `更多` 菜单。

   `数据源`、`代理`、`导出缓存`、`导入缓存`、`检查更新` 和 `启动检查更新` 都属于配置、维护或低频操作。它们应收进右侧菜单式入口，减少顶部一行的按钮数量。菜单项仍使用现有 icon 和简短标签，并保留 loading / disabled / checked 等状态。

3. 用户工具入口使用紧凑工具组。

   `指标`、`做T` 和 `策略` 属于围绕当前图表的用户工具。已确认 `指标` 和 `做T` 保持顶部直接可见，使用紧凑工具组放在刷新和标题之后；`策略` 在分时模式下不展示可触发入口，在 K 线模式下直接展示并触发 `stock.openStrategyPanel`。窄窗口空间不足时，次级工具可以压缩为 icon button，但不改变入口语义。

4. 当前证券标题保持可见但降低抢占空间。

   当前标题用于确认当前加载对象，应保留在顶部，但通过 `min-width: 0`、最大宽度和省略号处理，避免长名称挤压查询控件或菜单按钮。

5. 响应式策略优先保护查询链路。

   默认桌面窗口宽度下不应出现横向滚动条。窄窗口时，查询输入、视图切换、刷新和 `更多` 菜单仍应可用；次级工具可以隐藏标签、压缩为 icon button，或进入工具菜单。样式应使用明确的 flex/grid 约束，避免依赖文本自然宽度撑开整行。

6. 菜单构造应便于测试。

   实施时可以把 `更多` 菜单项构造提取为局部 helper 或小组件，使单测可以断言菜单包含数据源、代理、导入导出、检查更新和启动检查更新。React SSR 测试不一定会展开 Ant Design `Dropdown` overlay，因此测试不应只依赖静态 HTML 中是否直接出现所有菜单文本。

7. 文档按新入口位置同步。

   README 和应用内 `使用说明书` 中提到“顶部工具栏”的入口应同步为新的层级，例如“更多菜单中的数据源/代理/检查更新”和“工具组中的指标/做T/策略”。`CHANGELOG.md` 的 `Unreleased / <current package.json version>` 区块记录本次用户可见 UI 优化。

## Risks / Trade-offs

- [Risk] 用户习惯了所有按钮直接铺开，聚合后第一次可能找不到低频入口。→ Mitigation：菜单按钮使用清晰标签，例如 `更多` 或 `工具`，并保留图标和 tooltip；文档同步入口位置。
- [Risk] Ant Design `Dropdown` 菜单里的异步操作 loading 状态不如独立按钮明显。→ Mitigation：菜单项展示加载文案或禁用态，例如导入检查中禁用导入项；关键刷新按钮仍保留为直接可见主按钮。
- [Risk] 顶部工具栏过度压缩后影响 K 线日期输入效率。→ Mitigation：K 线参数仍直接可见，只有低频设置进入菜单；窄窗口下优先压缩次级工具而不是压缩日期输入。
- [Risk] 旧单测通过静态 HTML 查找按钮文本，聚合菜单后会失效。→ Mitigation：新增菜单项 helper 测试或交互测试，验证入口仍存在并绑定正确 action。

## Migration Plan

- 重构 `TopToolbar.tsx` 的布局分组，保留现有 props 和 ViewModel action。
- 使用 Ant Design `Dropdown` / `MenuProps` 聚合低频操作，并为启动检查更新提供等价的 checked/toggle 行为。
- 调整 `src/renderer/styles.css` 中顶部栏、分组、标题和窄窗口样式，移除对横向滚动的主要依赖。
- 更新 toolbar 相关测试，覆盖直接可见主操作、菜单项构造、K 线模式策略入口、缓存导入导出入口、更新检查和启动检查更新开关。
- 更新 README、应用内 `使用说明书` 和 `CHANGELOG.md`。
- 运行 `openspec validate optimize-top-menu-ui --strict`、`yarn test` 中相关 toolbar/文档测试、`yarn typecheck`，普通代码改动完成后运行 `yarn test`。

## Confirmed Defaults

- 右侧聚合菜单命名为 `更多`。
- 证券输入、自选、分时/K 线切换、K 线参数、刷新和当前证券标题保持直接可见。
- `指标` 和 `做T` 保持顶部直接可见。
- `策略` 仅 K 线模式直接展示；分时模式不展示可触发入口。
- `数据源`、`代理`、`导出缓存`、`导入缓存`、`检查更新` 和 `启动检查更新` 收入 `更多` 菜单。
- 默认桌面窗口宽度不横向滚动；窄窗口优先保留证券输入、视图切换、刷新和 `更多` 菜单，当前证券标题以省略号截断。
